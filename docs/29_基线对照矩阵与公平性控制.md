# 29 — 基线对照矩阵与公平性控制

> **状态**: v1.0（2026-08-27）
> **效力**: 定义投稿前必须补齐的基线模型清单、每条的公平性控制，以及"同口径"原则。基线比较只允许在同一队列、同一结局、同一评估协议下进行，禁止为让主模型好看而挑基线或挑子集。

---

## 0. 为什么现在必须补

当前主结果（MIMIC-III 内部）已经证明：路径模型（静态+15 路径，AUPRC 0.349 val / 0.309 holdout）**弱于**表格臂 B（0.582 val），其价值定位是"可核对低维解释层"而非"预警主模型"。一区审稿人会问三个问题：

1. 你的模型比 **现成临床评分**（SAPS II / SOFA / APACHE）强多少？——当前没有。
2. 你的模型比 **梯度提升 / 深度学习基线** 强多少？——当前只有你自己的 A/B/G 臂，缺外部通用基线。
3. 外部验证（eICU）上这些基线也同口径重跑了没有？——当前没有。

本节把这三件事固化成一张矩阵。

---

## 1. 公平性控制总原则（写死）

| 原则 | 内容 |
|------|------|
| **同队列** | 所有基线与主模型用完全相同的 landmark-eligible 队列（MIMIC holdout n=2537；eICU full） |
| **同结局** | 一律 landmark 后住院死亡，二元 |
| **同特征来源** | 基线能用的特征不超出主模型可用的静态变量 + 测量时序；禁止给基线喂主模型没有的"神特征" |
| **同评估** | 一律 AUPRC（主）+ AUROC + Brier + 校准曲线；AUPRC 因患病率敏感，跨站点比较必须标注患病率 |
| **同预处理** | 缺失处理、标准化、时间窗边界一致 |
| **同种子/划分** | MIMIC 侧用冻结 train/val/holdout；eICU 侧零训练 |
| **不事后挑** | 基线结果无论好坏都进表，失败不许删行 |

## 3. 每类基线的具体实现要求

### 3.1 临床评分重建（B0/B1/E1）

- **SAPS II**：需要 12 项生理最差值 + 年龄 + 入 ICU 类型 + 慢性病。MIMIC 与 eICU 都从 24h 内最差值重建；eICU 侧可从 `apacheApsVar` / `vitalPeriodic` 重建，但**统一用我们自己的重建函数**，不混用 eICU 原生 apache 分。
- **SOFA**：呼吸（P/F 比）、凝血（血小板）、肝（胆红素）、循环（MAP/血管活性药）、神经（GCS）、肾（肌酐/尿量）。注意：SOFA 含肌酐/尿量，与 AKI onset 有信息重叠，报告时必须声明"肾项与结局/纳入标准重叠"的局限。
- 缺失处理：按各评分原始手册（最差值取首个 24h；缺失项记 0 分但记录每项缺失率）。

### 3.2 梯度提升（B4/E4）

- 特征：静态协变量 + 48h 内 11 个检验的阶段汇总（如每个阶段的 mean/min/max/last），与 B 臂特征口径一致。
- 调参：MIMIC 侧 5 折分组 CV（按 SUBJECT），只搜 `max_depth ∈ {3,5,7}`, `learning_rate ∈ {0.01,0.05,0.1}`, `n_estimators` 早停。
- eICU 侧：直接加载 MIMIC 拟合模型预测，**不重训**。

### 3.3 深度学习时序基线（B5）

- 输入：48h 小时网格（与 Shapelet 同网格，缺失保留 mask）。
- 架构：单层/双层 LSTM，隐藏 64，加 mask 输入；输出 sigmoid。
- 训练：MIMIC train/val/holdout；早停只监控 val AUPRC。

## 5. 禁止事项（防止"挑基线"）

1. 禁止只报 AUROC 不报 AUPRC（患病率 0.145 时 AUPRC 才是主指标）。
2. 禁止给基线喂不同特征集（如给 XGBoost 喂 308 检验但给静态 logistic 只喂静态，然后声称 XGBoost 完胜）。
3. 禁止 eICU 上对任何基线重训或调参。
4. 禁止用 apacheApsVar 的 AKI/肌酐字段重建 APACHE 后再与主模型比死亡预测（那是结局泄漏）。
5. 禁止只报"路径模型 AUC 上升"而隐瞒事件侧 NRI 为负（MIMIC 已知为负，eICU 同样要拆）。

## 7. 结论口径（投稿前不得越过）

- 本文的路径模型 **预期在纯预测上弱于 B 与梯度提升**。这不影响其"可解释层"定位，但正文必须如实排序，不得用"我们超过了 SAPS II"这种只挑弱基线的说法。
- 只有满足 docs/28 §9 的四条成功标准后，才允许把 eICU 外部验证写成"可解释性跨站点迁移"的证据。
